Pila to Tapos — Technical Spec

One Next.js app running on the laptop, with no deployment: this is the blueprint for how the pages, the in-memory queue and the pre-written Magtanong answers fit together, and where each piece lives in the code.

Implements prd.md (as revised in 4-spec for the one-counter, two-visit process, and in 5-build for pre-written answers and a laptop-only build). Official-source research: devpost/research/bir-closure-sources.md. Everything on this page comes from devpost/spec.md.

Revised in 5-build (2026-10-22). The learner replaced live AI with pre-written cited answers and dropped deployment. This removes Supabase, Realtime, the Claude API, Vercel, and the in-app scanner. The app now runs as one server on the laptop. The data lives in a plan file and in the server's memory, the screens check for updates every 2 seconds, and a phone on the same Wi-Fi scans the TV's QR code with its own camera. The earlier choices and their reasons are kept under Decisions and Open Issues.

How this works, in plain language

Pila to Tapos is one Next.js web app running on your laptop. Each screen just opens a different address on the laptop.

PageOpened onWhat it is
/ and /planHer phone (or the laptop in phone view)Screen 1 and "Your plan" (with the Magtanong panel)
/lineHer phoneHer number, "Ikaw na!", "Balik ka sa [date]," "Tapos na!"
/counterThe laptop (staff)The Registration Officer counter
/tvThe laptop or TVThe panel for the counter, the spoken call, and the QR code
/teamThe laptopThe passcode-protected edit screen

A real phone reaches the laptop over the same Wi-Fi. The TV's QR code holds the laptop's local address (for example http://192.168.1.23:3000/join), and the phone's own camera opens it.

Where things live

The plan

Steps, documents, fees, time, situation questions, the common questions and their pre-written answers, and a citation for every item are one data file, content/plan/bir-closure.json, which the server reads. The team edit screen writes changes back to it.

The official BIR text

Three short, verified text excerpts stored as plain text files: RMC 47-2026, Citizen's Charter entry 28-A, and the RMC 84-2026 digest. Every quoted answer is checked word for word against them.

The queue

Numbers, who is waiting, who is called: in the server's memory while the laptop runs it. When staff tap "Call next," the server updates the queue. The TV, the counter, and her phone check for updates every 2 seconds, so they react within moments. Restarting the server clears the queue, which is handy between demo takes.

Her phone

Her ticks, answers, and journey (which visit she is on, her return date) live on her phone, in the browser's localStorage, a sticky note the browser keeps for one site. That is why there is no login.

How Magtanong works

The panel lists common questions. Each answer was written ahead of time from the official excerpts and shows its citation. When the source does not answer a question, the answer is the grey "not in the source" card. A check script confirms every quoted passage really appears in its source file, so nothing is invented. There is no AI call.

How the TV speaks

The browser's built-in speech says "Numero B-014, [counter]" with a Filipino voice if the browser has one. If not, it plays short clips the team records.

Why this shape

The proof of concept is shown on video, so one laptop server is enough. There are no accounts, no keys, no hosting, and nothing to pay for.

How the code is organized

Business rules never read files or memory directly. They receive what they need ("a plan repository," "a queue repository," "a clock") as arguments, and one file, the composition root, plugs in the real versions. The in-memory and file versions are product code, and they keep the business rules testable without the server running.

Architecture

Each layer imports only downward. Pages call server actions, server actions call services, services use ports, and the composition root decides which adapter sits behind each port.

Polling every 2 s through server actions, over the same Wi-Fi (http://<laptop-ip>:3000) Dashed grey box: pure domain rules (no IO) and the note that there are no external services

Business rules never import node:fs or touch memory directly. ESLint allows fs only in src/adapters/** and scripts/**. No external services, API keys, or accounts are needed.

Core Domain (pure rules)

What it does

Types and pure functions with no IO: Plan, Step, PlanDocument, Fee, Question, Citation, Ticket, Journey, and Result<T, E>.

  • checklistStatus(plan, ticks, answers) returns { missing, ready }. Hindi means not needed; Oo, Hindi ko alam, or no answer mean required.
  • addWorkingDays(date, n) skips Saturdays and Sundays in Asia/Manila.
  • diffPlan(snapshot, plan) returns { added, changed } item ids, for the "Na-update" banner.
  • formatTicketNumber(letter, seq) returns B-001.
  • validateCitations(plan, sources) returns the list of problems: an item without a citation, or a quote that does not appear word for word in the cited source text. It backs "no citation, no save" and the content check.
  • totalVisitTime(journey) sums both visits.

Core Ports (contracts)

What it does (hand-written contracts)

  • PlanRepository: getPlan(transactionId), saveStep, saveDocument, saveFee, saveMeta. Every save requires a citation and bumps the item's revision.
  • QueueRepository: issueTicket({ journeyId, visit, docsReady, issuedAt }), listWaiting(counterId), getCurrent(counterId), callNext(counterId, at), finish(ticketId, at), getTicket(id).
  • SourceTexts: get(sourceId) returns the excerpt text (used by validateCitations).
  • Clock: now(). Ids: uuid().

Core Services

What it does

Factories that take ports and return functions. Types are ReturnType<typeof createX>.

  • Plan service: getPlan(). The questions and explanations come with the plan.
  • Queue service: issueTicket, callNext, finishVisit, getTicket, boardState (current number plus waiting list). It refuses callNext on an empty list with { ok: false, error: "empty" }.
  • Team service: checkPasscode, plus saveStep, saveDocument, saveFee, saveMeta, each rejecting a missing citation (citation_required) or a quote not found in the source (quote_not_in_source).

Core Adapters

What it does

  • File plan repository (server-only): reads and writes content/plan/bir-closure.json, writing through a temp file and a rename so a crash cannot leave half a file. It is the only server code that imports node:fs (besides the sources reader and scripts/).
  • Source texts reader (server-only): reads content/sources/*.txt plus sources.json (title, URL, effective date).
  • In-memory queue repository (server-only): product code. An array of tickets kept on globalThis, so it survives hot reload. Numbers restart at B-001 each day (Asia/Manila) and on a server restart.
  • Server actions are adapters too: parse input, call exactly one service method, and map the Result to a plain serializable response. getTicket and boardState are what the screens poll.

Files

  • src/adapters/file/: plan-repository.ts, source-texts.ts

Core Composition root

What it does

src/composition-root.ts (server-only) builds the services with the file plan repository, the source texts reader, the in-memory queue repository, the system clock, and crypto.randomUUID, and caches them on globalThis. Only server actions and server components call it. Domain and service tests call createXService with plain object fakes.

Join (QR target)

src/app/join/page.tsx is a client page. It reads the journey from localStorage. PRD: prd.md > Getting a Number.

Phone Magtanong (pre-written answers)

What it does

In src/app/plan/components/. PRD: prd.md > Asking Questions (Magtanong).

  • AskSheet (shadcn Sheet from the bottom): the question list. Tapping one shows its answer, and a "Mga tanong" back button returns to the list.
  • AnswerCard (normal style): the answer text, then each citation as a quoted passage with its source title and locator, linking to the official PDF.
  • NotInSourceCard (grey, info icon): "Hindi ito direktang sinasagot ng opisyal na source," the related quote labeled "Related, not a direct answer," who to ask, and "Gabay lang ito, hindi legal o tax advice."
  • DocumentExplainer: the "?" on a document opens the same sheet showing that document's explanation and citation. The "Hindi ko alam" nudge opens it too.

The sheet overlays the page and does not navigate, so the scroll position is kept. The questions and answers are not generated at runtime: they are read from the plan file, already loaded with the plan. There is no free-text box and no AI call.

Queue (server memory)

tickets: { id, day ("YYYY-MM-DD", Asia/Manila), seq, number ("B-001"), journeyId, visitNo, counterId, docsReady, status: "waiting" | "called" | "done", issuedAt, calledAt?, doneAt? }[], held on globalThis. There is no personal data. A server restart clears it.

Her phone (localStorage key pila:v1)

{
  journeyId: string,                  // uuid, created on first plan visit
  ticks: Record<docId, true>,
  answers: Record<docId, "oo" | "hindi" | "hindi_ko_alam">,
  seen: { revision: number, items: Record<itemId, number> },  // for "Na-update"
  visits: { 1?: { ticketId, issuedAt, doneAt? }, 2?: { ticketId, issuedAt, doneAt? } },
  demoSkip: boolean,
  soundOn: boolean
}

When she leaves and comes back

  • Ticks, answers, and visits stay until "Tapos na!" (which clears ticks and answers) or "I-reset."
  • The ticket's live status always comes from the server.
  • If the server was restarted and her ticket no longer exists, /line says "Hindi na makita ang number mo. Kumuha ulit." and unlocks a new scan.
  • After a plan change, ticks are kept for unchanged documents and dropped for changed ones, and new documents start unticked.

Server-side state on the TV and counter

None of their own. They poll boardState every 2 s, and the queue they read lives in the server's memory.

Run with a real phone

  1. Find the laptop's Wi-Fi address with ipconfig getifaddr en0.
  2. Set NEXT_PUBLIC_APP_URL=http://<that-address>:3000 in .env.local.
  3. Start the server listening on the network with npm run dev:lan, which runs next dev -H 0.0.0.0. Allow macOS's "accept incoming connections" prompt.
  4. On the phone, open http://<that-address>:3000, or scan the TV's QR code with the phone's camera.

Reset between demo takes

Restart the server to clear the queue. On the phone, use the "I-reset" link at the bottom of the plan to clear the ticks and the journey.

Important failure modes

The phone can't reach the laptop

A different Wi-Fi, Wi-Fi that blocks devices from seeing each other, or the macOS firewall. Use the phone's hotspot with the laptop joined to it, and allow incoming connections. As a last resort, record with the laptop's phone view only.

The laptop's address changes

A new network. /tv prints the address under the QR code. Update NEXT_PUBLIC_APP_URL and restart.

No Filipino voice on the TV's browser

The pre-recorded clips play instead. Browsers block sound until a tap, so the TV always starts with a "Simulan ang TV" tap.

A quoted answer drifts from the official text

npm run check:content fails the build step and names the item. The team edit screen refuses a save the same way.

The server restarts mid-demo

The queue empties, and her phone says "Hindi na makita ang number mo. Kumuha ulit." Treat it as a reset.

localStorage is blocked

Private browsing: the app still works for the session, but ticks will not survive a reload. A small note says so.

What was simplified and why

Pre-written answers instead of live AI

Learner decision in 5-build. The proof is shown on video, so a curated list of questions with quoted, cited answers proves the kernel without an API key, cost, or the riskiest integration. The fuller version (Claude with the citations feature) is described under Decisions.

A laptop server instead of a hosted database and realtime service

Learner decision in 5-build. One process keeps the queue in memory, and screens poll every 2 s. The fuller version would need Supabase (or similar), Realtime, and hosting.

The phone's own camera instead of an in-app scanner

Phones require HTTPS for the camera inside a website, and a local address is not HTTPS. The QR code is a plain URL, so the native camera works.

The plan is a JSON file instead of database tables

It has the same shape, and the team screen writes back to it.

Self-reported readiness

The server trusts docsReady.

Weekends only, no holidays

The return date skips weekends, not Philippine holidays.

Open staff and TV pages

They are open URLs on the local network; only the team edit screen has a passcode.

One of everything

One office, one counter, one transaction, and the number letter is always B.

Demo switch

A switch, labeled on screen, simulates the 3 working days.

The kernel is not faked: the requirements, quotes, and citations come from the real official text, and a script checks every quote.
