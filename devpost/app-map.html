Pila to Tapos — app map

Pila to Tapos helps a freelancer close a BIR (Philippine tax office) registration. It builds a plan from official sources, issues a queue number, tells her when she is called, lets her come back for the second visit, and marks the closure done: plan, number, called, come back, done.

The app has a few main pieces:

  • One Next.js app running on a laptop, with no deployment.
  • A plan file with official excerpts, content/plan/bir-closure.json.
  • An in-memory queue (nothing is saved to a database).
  • Three screens: the phone (/line, /plan), the staff counter (/counter) and the TV (/tv). They check for changes every 2 seconds.
  • The phone saves her progress in localStorage (src/lib/phone-storage.ts).
  • An English / Filipino switch (?lang=en or ?lang=fil).

Reference route (not toured interactively)

This is a reference route for the same action. It was read from the code, not walked through live with the learner. Search for the anchor name to jump to each spot.

Stop 1 — the tap: src/app/counter/components/counter-screen.tsx

Anchor: callNext(counter.id) inside CallNextButton's onCall. The button (call-next-button.tsx) is the big "Call next" the staff see; tapping it runs the server action, then the counter screen refreshes its own board.

Stop 2 — the rule: src/services/queue-service.ts

Anchor: callNext. The server action (src/app/actions/queue.ts) only passes the counter id to this service. The service decides what is allowed (for example it refuses while a number is still called, so staff must tap Done first) and asks the repository to mark the next waiting ticket as called, with a timestamp from an injected clock.

Stop 3 — what the visitor sees: src/lib/use-poll.ts, then the two screens

Anchors: usePoll, Announcer, CalledOverlay. The in-memory repository (src/adapters/memory/queue-repository.ts, callNext) holds the new "called" status. Within about 2 seconds the TV's usePoll sees a new call, so useNewCall triggers Announcer and speak (pre-recorded clips from public/audio/). The phone's usePoll in line-screen.tsx sees the status change, plays a chime and shows CalledOverlay.

A practice to reuse

Late in the build, the plan screen was called "not friendly". That is vague, so before changing anything it was turned into specific, checkable observations, then built and re-measured:

  • Page height at phone size: about 5,800 px down to about 3,000 px.
  • Citation chips: 13 down to 3 "Where is this from?" links (the citations stay one tap away).
  • One clear "what's next" action at the top of the plan.

The measurements (5,833px to 3,003px tall, 13 to 3 citation buttons) are recorded in devpost/checklist.md (section "Final Review"); the plan screen's intent is in devpost/prd.md (section "Your Plan").

The reusable habit: describe what you see, what you expected, and a measurable check, then let the agent build against that.

A second example of the same idea turns a trust requirement into an automatic check. Every citation quote must appear word for word in its official source, and npm run check:content (scripts/check-content.ts, which calls validateCitations in src/domain/citations.ts) fails if one does not.

Run it again

  1. npm install
  2. npm run dev on the laptop, or npm run dev:lan to use a real phone on the same Wi-Fi.
  3. Open /, /counter and /tv. Add ?lang=en for English (?lang=fil for Filipino).
What to look for in the first run

Get a number on the phone view, tap "Call next" on /counter, and watch /tv and the phone react within about 2 seconds. The TV needs one tap first (the start overlay) before the browser lets it play sound.
